# CareMap AI — 울산 시범분석 MVP

울산광역시의 행정동별 고령인구와 노인돌봄지원플랫폼 현황을 살펴보고, 구·군 단위의 추가 거점 시나리오를 비교하는 초기 의사결정 지원 시제품입니다.

## 실행

Node.js 18 이상에서 저장소 루트에서 실행합니다.

```sh
npm start
```

브라우저에서 http://127.0.0.1:8765/ 를 엽니다. 서버는 보안을 위해 localhost(127.0.0.1)에만 바인딩합니다. OSM 배경지도 타일에는 인터넷 연결이 필요합니다.

`npm start`는 시작 전에 `data/`의 기준 CSV를 읽어 화면용 데이터 파일과 구·군 요약 CSV를 생성합니다. 화면 데이터는 CSV를 별도로 복사해 관리하지 않습니다.

## 현재 기능

- 55개 행정동의 65세 이상 인구를 지도에 원으로 표시하고 구·군별 필터 제공
- 고령인구 규모순 행정동 탐색
- 공개된 노인돌봄지원플랫폼 17곳 목록과 구·군별 시설 수 표시
- 선택한 구·군의 플랫폼 수를 1~3곳 늘려 보는 단순 비율 시나리오
- 데이터 기준일과 출처, 해석 한계를 화면에 표시

## 데이터와 한계

- 행정안전부 주민등록 인구 자료: 기준일 2026-10-31, 울산 55개 행정동 집계
- 울산광역시 노인돌봄지원플랫폼 자료: 기준일 2025-12-31, 17개소
- 시설 정원, 인력, 대기자, 서비스 권역, 이용량 자료는 확보하지 못했습니다. 따라서 실제 미충족 돌봄 수요나 서비스 접근성을 확정하지 않습니다.
- 지도 점은 행정동 대표 좌표에 집계 인구를 표시합니다. 시설별 좌표는 확보하지 못해 시설 핀으로 표현하지 않습니다.
- 시나리오는 시설 수만 바꿔 `65세 이상 인구 ÷ 플랫폼 수`를 비교합니다. 새 시설의 위치·수용능력·서비스 권역을 반영하지 않으며, 지도에 입지를 표시하거나 접근성 개선 효과를 추정하지 않습니다.
- 도로망 이동시간 분석, 서비스 커버리지 계산, 후보지 입지 최적화는 현재 구현되어 있지 않습니다.
- 현재 버전은 예측 모델을 학습한 AI가 아니라 공개자료 기반의 분석·시나리오 MVP입니다.

## 데이터 범위와 확장 계획

- 현재 MVP는 행정안전부의 울산 행정동 인구 집계와 울산시 노인돌봄지원플랫폼 시설 목록을 사용합니다. 개인별 사회보장 기록이나 한국사회보장정보원 내부 시스템 데이터는 사용하지 않습니다.
- 울산시는 노인돌봄지원플랫폼을 재가노인지원서비스센터로 안내합니다. 이는 울산 지역의 서비스 분류이며 전국 장기요양기관 등 다른 시설 유형과 합산하지 않습니다. [울산시 안내](https://www.ulsan.go.kr/u/welfare/contents.ulsan?mId=001006002000000000)
- 전국 확장은 아직 구현되지 않았습니다. 다음 단계에서 지역별 원래 서비스 분류를 보존하고 공통 서비스 유형으로 매핑한 뒤, 두 번째 지자체 자료로 코드·기준일·누락률을 검증해야 합니다.
- 화면은 정적 HTML·Leaflet과 Node.js 로컬 서버로 구성됩니다. Next.js·FastAPI·PostGIS·OR-Tools는 현재 구현에 포함되어 있지 않습니다.
- 좌표는 OpenStreetMap 검색 결과이며 CSV에 OSM 객체 유형과 ID를 기록합니다. node·way·relation 및 행정복지센터 검색 결과가 섞여 있어 일관된 행정구역 중심점으로 볼 수 없습니다. 정비 전에는 접근성·거리 분석에 사용하지 않습니다.

## 다음 단계 후보

접근성이나 거점 배치 효과를 분석하려면 시설 좌표와 서비스 유형을 확인하고, 공간 경계·이동 네트워크·분석 기준을 추가해야 합니다. 최적화 결과를 제시하기 전에는 현재 배치와 대안 배치를 같은 조건으로 비교하고, 정원·대기자 정보가 없는 한 실제 공급량이나 미충족 수요로 해석하지 않습니다.
