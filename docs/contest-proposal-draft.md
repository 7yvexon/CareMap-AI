# CareMap 제안서 본문 초안

작성 기준: 2026-11-15 저장소 `d221155` 기준

> 내부 초안이며 공식 제출 양식이 아니다. 최신 지정 양식의 문항·분량·서명 요건에 맞춰 옮기기 전에 내용을 대조한다. `[팀명]`, `[대표자]`, `[팀원]`은 실제 정보로 채운다. 현장 평가와 발표 장비 검증 전에는 성능·효과 수치를 주장하지 않는다.

## 아이디어명

**CareMap: 자료의 범위와 근거를 보여주는 전국 사회서비스 탐색 지도**

## 1. 제안 배경과 해결하려는 문제

지역 주민이나 현장 담당자가 필요한 사회서비스를 찾을 때는 지역, 서비스 유형, 제공기관 정보가 여러 공개 자료에 나뉘어 있다. 이용자는 자신에게 필요한 도움을 어떤 유형으로 찾아야 하는지 알기 어렵고, 현장 담당자도 지역별 후보를 모아 기준일과 원자료를 다시 확인해야 한다.

CareMap은 이 문제를 현장 조사로 확정한 것이 아니라 검증이 필요한 문제 가설로 다룬다. 실제 이용자 상담 문장이나 개인별 복지 이력은 수집하지 않는다. 서비스 후보가 지역별로 얼마나 부족한지 판정하거나 지원 자격을 예측하는 기능도 제공하지 않는다.

## 2. 제안 서비스

CareMap은 전국 공개자료를 행정구역과 기준일에 따라 살펴보고, 사용자가 입력한 필요에 가까운 서비스 유형과 원자료 후보를 이어서 확인하는 웹 시제품이다.

1. 사용자가 시도와 시군구를 선택하고, 필요한 경우 읍면동 경계를 확인한다.
2. 지도와 요약에서 주민등록 인구, 공개 서비스 기록, 복지시설 통계를 원천별로 확인한다. 서로 다른 자료를 하나의 복지 점수로 합치지 않는다.
3. 사용자가 “병원에 갈 때 같이 가 줄 사람이 필요해요”처럼 합성 또는 비식별 문장으로 검색한다.
4. 의미검색을 켠 경우 문장과 서비스 유형 설명의 유사 후보 최대 3개를 보여준다. 사용자가 직접 유형을 골라야 해당 의미 유형이 검색에 추가된다. 기존 규칙 분류와 입력어 검색도 함께 사용한다.
5. 후보 카드에서 프로그램명·서비스 분류·제공기관·주소·연락처·원천 자료를 확인하고, 실제 운영과 이용 가능 여부는 기관에 문의한다.

검색 결과는 의뢰나 이용 확정이 아니라 다음 확인을 돕는 탐색 후보다. 읍면동별 서비스 기록이 없는 원천은 상위 시군구로 검색 범위를 표시한다.

| 행정안전부 주민등록인구, 2026-10-31 | 0~17세 및 65세 이상 인구, 65세 이상 1인 세대의 지역별 집계 | 인구·1인 세대는 돌봄 필요, 고립, 지원 자격을 뜻하지 않는다. |

| 공공데이터포털 지역아동센터 표준데이터, 2026-11-14 수집본 | 2,570개 원자료 행 중 검토 후보 6행을 분리하고 2,564행을 집계해 기록 상태를 지도와 전국·선택 지역 요약에 별도 표시 | 256개 시군구 중 146곳에서 기록이 관측되고 110곳은 이 수집본에서 미관측이다. 미관측은 센터 부재나 복지 공백을 뜻하지 않는다. 행 수는 고유 시설 수나 수용력을 뜻하지 않는다. |

행정동 인구자료 3,620개 코드 중 3,558개가 2026-10-01 기준 경계와 일치한다. 경계가 없는 62개 지역을 선택하면 화면은 상위 시군구 범위로 표시하고 이를 알린다. 행정구역의 새 경계나 코드가 확인되기 전에는 임의의 폴리곤을 만들어 넣지 않는다.

## 4. AI의 역할과 안전한 사용

브라우저의 multilingual-e5-small 임베딩은 검색 문장과 공개 서비스 중분류 설명의 유사도를 계산해 탐색 출발점을 제안한다. 이 모델은 사회복지 질의로 미세조정되지 않았고, 점수는 확률·정확도·지원 자격이 아니다. 범위 밖 질문에도 가까운 유형이 제시될 수 있으므로 유형 선택은 사용자에게 맡긴다.

모델 오류나 분석 시간 초과가 발생하면 해당 검색은 규칙·키워드 기준선으로 이어진다. 반복 지연을 줄이기 위해 이 경우 AI 추천 옵션을 자동으로 끄고, 다시 시도하려면 사용자가 옵션을 켜도록 했다. 입력 문장은 외부 생성형 AI 추론 API로 보내지 않지만, 첫 실행에는 모델 파일을 내려받아야 한다. 개인정보가 든 상담 문장은 입력하지 않도록 안내한다.

## 5. 차별점과 사회적 가치

CareMap은 지역별 인구나 시설 기록을 복지 결핍 점수로 환산하지 않고, 원천별 기준일·관측 단위·누락 범위를 사용자에게 함께 보여준다. 지역 자료 미관측을 서비스 부재로 오해하지 않도록 하고, AI가 유형을 결정하거나 자격을 판단하는 대신 사용자가 유형을 확인한 뒤 원자료 후보를 살펴보게 한다.

이 설계는 노인·아동 등 특정 집단에 위험 점수를 부여하거나 개인을 분류하지 않는다. 누구나 같은 공개 집계와 검색 기능을 이용하며, 실제 지원 여부는 해당 기관의 운영 정보와 이용 기준으로 확인한다. 이러한 설계가 실제 이용자의 탐색 시간을 줄이는지는 아직 측정되지 않았으며, 다음 단계에서 현장 검토로 확인한다.

## 6. 구현 현황과 검증 계획

전국 시도·시군구 필터, 행정구역 지도, 노인 관련 현황, 아동 인구 참고 모드, 원자료 기반 서비스 검색, 선택형 의미 유형 추천을 포함한 시제품이 구현되어 있다. 앱이 동작한다는 사실과 검색이 현장에서 유효하다는 주장은 구분한다. 의미검색의 최신 변경은 구문 검사를 통과했지만, 현재 실행환경에서는 로컬 API 소켓 연결이 막혀 최신 HEAD의 브라우저 동작 확인은 완료하지 못했다.

| 다음 검증 | 방법 | 공개할 결과 |
| --- | --- | --- |
| 유형 추천의 적절성 | 현장 담당자 2명이 합성 질의 20개의 기준 유형을 독립 분류하고 규칙·의미검색 결과를 비교 | 검토자 수, 평가 가능 문항, Top-1, Recall@3, 의견 불일치와 제외 사유. 검토 전에는 수치를 제시하지 않는다. |
| 근거 후보의 유용성 | 두 담당자가 결과 카드와 원자료 필드를 보고 질문과의 관련성을 평가 | 후보 근거 적합도와 문제·오해 가능 사례. 서비스 운영·자격 판단은 평가하지 않는다. |
| 시연 신뢰성 | 발표에 사용할 기기에서 첫 모델 다운로드, 캐시 재사용, 실패 fallback, 지도·지역 선택, 네트워크 없는 조건을 리허설 | 기기·브라우저·기준 커밋, 대기시간, 화면 캡처, 실패와 복구 결과 |
| 데이터 갱신 | 다음 공식 파일의 기준일·코드·누락·지역 연결을 이전 자료와 대조 | 수집일과 원천별 변경 기록. 결측을 시설 부재로 해석하지 않는다. |

## 7. 발전 계획과 현장 적용

초기에는 복지관·지자체 담당자와 합성 질의 및 후보 근거를 검토하고, 검색 결과의 표현과 실제 연락 경로가 이해되는지 확인한다. 다음으로는 발표 기기에서의 모델 로딩과 오류 복구를 반복해 시연을 안정화한다. 이후에는 공공 원천의 갱신 책임자와 기준일, 행정구역 코드 대응, 제공기관의 운영 여부를 사람 검토로 확인하는 절차를 정한다.

기관 협약, 실제 주민 의뢰, 서비스 이용 결과, 운영 예산은 아직 확보되지 않았다. 이를 완료된 성과로 표현하지 않고, 현장 파일럿과 갱신 책임·예산을 다음 단계의 조건으로 제안한다.
