# 전국 아동·노인 복지자원 원천 후보 조사

조사일: 2026-11-14 · 범위: 전국 단위 아동·노인 자원 중 기존 지역아동센터 표준데이터와 전국어린이집 표준데이터를 되풀이하지 않으면서 시도·시군구 비교가 가능한 원천 후보. 현재 저장소의 런타임·화면·원본 자료는 변경하지 않았다.

## 기존 자료와 중복 기준

현재 프로젝트는 지역아동센터 표준데이터 2,570행을 시군구별 기록 상태로 집계하고, 국민건강보험공단 통합돌봄 서비스 자원 90,081행을 시도·시군구별 서비스 프로그램 기록으로 집계한다. 보건복지부 복지시설유형별 입소정원·생활자 자료는 2025년 12월 최신분 4,230개 지역-시설유형 행을 보여 주는 집계 자료이며, 기관별 위치 목록은 아니다. 이 자료의 범위와 한계는 [data-scope.md](data-scope.md)에 정리되어 있다.

중복 판정은 다음처럼 구분했다.

- 전국 지역아동센터 표준데이터와 전국어린이집 표준데이터는 후보에서 제외한다. [지역아동센터 표준데이터](https://www.data.go.kr/data/15129438/standard.do)와 [전국어린이집 표준데이터](https://www.data.go.kr/data/15013108/standard.do)가 기존 기준이다.
- 노인 장기요양기관·노인여가시설은 두 기준 데이터의 대상과 다른 자원이다. 다만 장기요양기관은 현재 NHIS 통합돌봄 프로그램 자료와 같은 기관이 포함될 수 있다. 기존 90,081행에는 기관 고유번호가 없어 두 자료 사이의 중복률은 현재 검증할 수 없다. 이를 한 기관 수로 합산하지 않는 조건으로만 후보로 본다.
- 노인여가시설은 기존 보건복지부 집계 중 노인여가복지시설 유형과 주제가 겹치지만, 해당 원천은 기관별 위치 목록을 제공한다고 설명한다. 기관 목록과 집계 행은 별도 지표로 취급해야 한다.
- 아동급식카드 가맹점은 지역아동센터와 다른 유형의 사용처 자료다. NHIS의 식사지원 프로그램 기록과 주제는 겹칠 수 있으나, 가맹점 위치·운영시간이라는 별도 정보를 줄 수 있다. 시설 수나 아동 돌봄 수요와 합산하지 않는다.

## 아동급식카드 가맹점 자료: 전체 원본 미검증

[공식 표준데이터 페이지](https://www.data.go.kr/data/15034530/standard.do)는 전국 통합 자료의 전체 다운로드에 API를 사용하라고 안내한다. 화면 다운로드는 5만 행으로 제한되고, 개별 지자체 파일은 월초에 병합되므로 시점 차이가 있을 수 있다. 페이지에는 제공기관 목록 153건이 표시되지만 이는 행 수나 시군구 커버리지가 아니다. 미리보기에는 행별 `데이터기준일자`가 표시되지만 전체 자료의 기준일 범위는 확인되지 않았다.

공식 API 주소는 `https://api.data.go.kr/openapi/tn_pubr_public_chil_wlfare_mlsv_api`이며 `pageNo`, `numOfRows`, `type`을 제공하고 페이지 크기는 최대 1,000행이다. 포털 설명에는 개발 계정 트래픽 10,000회가 표시된다. 이번 조사 환경에서는 `api.data.go.kr` DNS 조회가 실패했고 API 인증키도 없어 전체 응답을 받지 못했다. 공식 페이지의 필드·샘플 행만 확인했으므로 실제 전체 행 수, 날짜 범위, 좌표 오류·누락, 중복률, 지역별 커버리지는 확정하지 않는다.

공식 미리보기의 제물포구 행은 `시군구코드` 28140을 쓰지만 현행 CareMap 행정 자료의 `sigunguCode`는 28125다. 이 차이를 코드로 바로 연결하면 오분류할 수 있어 좌표 유효성을 먼저 검사하고 현행 경계에 공간 결합하는 방식을 검토한다. 페이지는 무료라고 표시하지만 일반 이용허락 안내를 연결하므로 상호·주소·전화번호를 포함한 가맹점 정보를 재배포하기 전 이용조건을 확인해야 한다. 이 자료는 급식카드 사용처 탐색 레이어 후보이며, 영업·결제 가능 상태, 아동의 이용량·자격·식사 수요를 증명하지 않는다.

## 추가 아동·급식 후보: 공식 메타데이터 확인, 실물 원본 미확보

### 아이돌봄 제공기관·월별 신청현황 API

[한국건강가정진흥원 제공기관 API](https://www.data.go.kr/data/15078130/openapi.do)는 기관 코드·명칭, 시도·시군구, 서비스 지역, 주소·위경도와 행별 기준일 필드를 안내한다. [월별 신청현황 API](https://www.data.go.kr/data/15079828/openapi.do)는 `crtrYm`, 돌봄 유형, 연령×소득지원 구간별 신청 건수를 제공하며, 두 명세의 `childCareInstNo`를 연결키로 쓸 수 있다. 두 API는 REST의 JSON/XML 형식이며 무료·이용허락범위 제한 없음으로 표시된다. 포털 수정일은 각각 2025-06-17 및 2025-06-25이고 갱신주기는 실시간으로 표시된다. 신청현황의 실제 시작·끝 월은 원 응답을 확보하지 못해 확인하지 않았다.

두 API 모두 서비스키가 필요하다. 공식 페이지의 `totalCount`는 명세 예시 응답값이므로 최신 전국 기관 수나 신청 건수로 인용하지 않는다. 이 조사에서는 인증키 기반 호출을 하지 않았고, 실제 행 수·월 범위·지역별 커버리지·필드 결측을 검증하지 못했다. 제공기관의 주소·좌표는 현행 행정경계와 공간 결합할 수 있지만 신청현황에는 아동 거주지가 없으므로 집계 위치는 제공기관 또는 표시된 서비스 지역으로 한정해야 한다.

신청 건수는 신청 집계로 해석한다. 이를 고유 아동 수, 실제 서비스 이용, 대기자 수나 미충족 수요라고 부르지 않는다. 기존 지역아동센터 및 급식카드 자료와는 다른 서비스 유형이지만, NHIS 통합돌봄 프로그램에 같은 기관이 포함되는지는 공통 식별키가 없어 미확인이다. 별도 지표로 유지하고 기존 자원 수와 합산하지 않는다.

### 전국무료급식소 표준데이터

[공식 표준데이터 페이지](https://www.data.go.kr/data/15013107/standard.do)는 지자체·공공기관이 운영하거나 공적 지원을 받는 급식소를 대상으로 하며, 급식 대상은 노인·아동·저소득층 등으로 설명한다. 시설명, 운영주체, 급식대상, 주소·좌표, 운영요일·시간, 데이터 기준일 필드를 안내한다. CSV/XLS/XML/JSON/RDF 및 API를 제공한다고 표시하며, 화면 다운로드는 최대 5만 행, API 페이지는 최대 1,000행으로 안내한다. 개발계정 API 한도는 10,000회로 표시된다.

카탈로그에는 연 1회 갱신 및 2026-06-22 수정일이 표시되지만 개별 지자체 자료는 월초 취합으로 늦게 반영될 수 있고 행별 기준일도 다를 수 있다. 제공기관 206건은 제공기관 수이지 급식소 수나 전국 커버리지로 쓰지 않는다. 무료로 표시되나 구체 재사용 조건은 일반 이용허락 안내만으로 확정하지 못했다. 실제 전체 파일/API 응답을 받지 못해 행 수·날짜 범위·좌표 품질·중복·지역 커버리지는 미검증이다.

위경도에서 현행 행정경계로 결합하는 방식을 검토할 수 있으나 공식 설명에서 행정코드 제공 여부는 확인하지 못했다. 지역아동센터와 아동급식카드 가맹점은 다른 시설·서비스 채널이지만 NHIS 식사지원 기록이나 MOHW 시설 집계와 같은 기관이 포함될 수 있다. 공통 식별키가 없어 중복은 미확인이다. `급식대상`은 자유기재이므로 자격이나 이용 가능성을 자동 판정하지 않으며, 화면에는 운영정보의 기준일과 방문 전 확인 필요성을 표시해야 한다.

### 후순위: NHIS 장기요양기관 시설별 현황 파일

[공식 파일 페이지](https://www.data.go.kr/data/15124763/fileData.do)는 전국 XLSX, 반기 갱신, 무료 및 이용허락범위 제한 없음으로 표시한다. 최신 2026년 6월 자료는 지자체 행복e음 지정자료 기반(2026-06-10 기준)이라고 설명하지만 최신판에 정원·현원·종사자 필드가 있는지는 확인되지 않았다. 2025년 4월 이전 자료에는 해당 필드가 있으나 일부 기관 미입력 결측이 설명되어 있다. 원본과 최신 스키마를 확보하지 못했고 기존 MOHW 시설 집계·NHIS 프로그램 자료와의 중복도 검증하지 않아 우선순위를 낮춘다.

## 다음 검증 순서 (통합 승인 아님)

1. 아이돌봄 제공기관·월별 신청현황 API의 서비스키를 확보할 수 있는지 확인한다. 접근 가능하면 실제 응답의 기간·기관키 연결·결측·지역 범위를 검증하고, 신청 건수는 별도 집계로만 다룬다. 키와 응답이 확인되기 전에는 화면·생성 자료에 넣지 않는다.
2. 전국무료급식소 표준데이터의 전체 파일/API 응답과 재사용 조건을 확인한다. 행 수·기준일·좌표 품질·중복·시군구 범위를 검증한 뒤 지도 레이어로 쓸지 판단한다. 제공기관 수를 시설 행 수로 쓰지 않는다.
3. 전국아동복지급식정보표준데이터의 전체 응답을 공식 API로 확보할 수 있는지 확인하고, 행 수·기준일 범위·좌표 유효성·중복·시군구 관측 범위와 재사용 조건을 검증한다. 현재 환경에서는 API 호스트에 연결되지 않아 실제 응답을 받지 못했다. 원본 검증 전에는 화면·생성 자료에 넣지 않는다. 시군구 코드는 현재 행정코드와 다를 수 있어 좌표 기반 행정경계 결합을 우선 검토한다.
4. 한국문화정보원 노인여가시설 CSV의 실제 다운로드 가능 여부, 사용 조건(KOGL 표시), 컬럼 정의와 표본 지역 범위를 확인한다. 실제 파일과 재사용 조건이 확인되면 기존 노인시설 유형별 집계에 없는 시설 위치정보를 더할 수 있는지 평가한다.
5. NHIS 장기요양기관 시설별 파일은 최신판의 열·기관키·지역 범위와 기존 자료와의 중복을 실제로 확인할 수 있을 때만 재검토한다. 장기요양기관 검색 API도 기관 식별자·유형·지역 코드를 보완하는 후보로 유지하되, 실제 응답과 기존 NHIS 자료의 중복을 확인하기 전까지 통합하지 않는다.

위 순서는 추가 정보의 잠재력에 따른 **조사 우선순위**다. 어느 자료도 현재 CareMap에 통합할 수 있도록 승인된 것은 아니다.

## 기관별 목록 API 후보: 장기요양기관 검색 서비스

공공데이터포털의 NHIS API 명세에는 두 검색 기능이 있다. **전국 기관 집계 후보는 ‘장기요양기관 검색 목록 조회’ 기능**으로 한정한다. 이 기능은 시도 코드를 필수 입력으로 받고 시군구 코드로 범위를 좁힐 수 있으며, 응답 필드로 `longTermAdminSym`(기관 식별자), `adminPttnCd`(기관 유형 코드), `adminNm`(기관명), `siDoCd`, `siGunGuCd`, `longTermPeribRgtDt`(지정일), `stpRptDt`(등록일)를 제시한다. 이 필드만으로는 도로명 주소, 좌표, 정원, 이용자 수, 대기자 수, 현재 운영 상태를 확인할 수 없다.

같은 명세의 **‘청구그린기관 목록 검색 조회’는 별도 기능**이다. 여기는 읍·면·동 코드, 도로명 코드, 건물번호, 전화번호 일부가 포함될 수 있지만, 설명상 청구그린기관 검색이다. 전체 장기요양기관 목록과 같은 범위라고 확인되지 않았으므로 전국 커버리지 집계에 섞지 않는다.

### 파일/API 접근 확인 결과

- 공식 상세 페이지, XML REST 형식, API 기본 주소, 요청·응답 필드, 무료·이용허락범위 제한 없음, 실시간 갱신 표시는 확인했다. 상세 페이지는 활용신청 및 인증키를 안내하며 개발단계 트래픽 한도는 일 10,000회로 표시된다.
- API 기본 주소를 실제 열어 응답을 확인하려 했으나, 사용한 웹 확인 도구가 `apis.data.go.kr` 응답을 열지 못했다. 인증키를 사용한 요청은 하지 않았다. 따라서 실제 HTTP 성공, 페이지네이션 동작, 결과 건수, 전체 지역 커버리지는 **미확인**이다. 이것은 API가 고장났다는 증거가 아니다.
- API 문서는 시군구 코드 조회를 지원하지만 기준일 또는 응답 시각 필드는 명세에 보이지 않는다. 포털의 2025-11-10 수정일과 실시간 갱신 표시는 원 데이터의 정확한 기준일을 대신하지 않는다.
- 행 단위 고유 기관 수는 `longTermAdminSym` 중복 제거로 산출할 수 있을 것으로 보이나, 실제 응답에서 중복 규칙을 확인하기 전까지 그 가정은 검증되지 않았다. API의 기관 유형 코드 사전도 코드표를 확인해야 해 유형별 집계는 아직 만들 수 없다.

### 안전하게 쓸 수 있는 범위

인증키를 발급받아 공식 API 응답과 코드표를 확인한 뒤, 개인·기관 연락처나 개별 식별자를 저장하지 않고 **시군구 × 검증된 기관 유형별 고유 기관 수**만 별도 집계하는 방식이 가장 보수적이다. 행정동 인구 파일의 행정기관코드와 API의 법정동 코드는 같은 체계라고 가정하지 말고, 공인 코드표를 이용해 시군구 수준에서 연결해야 한다.

화면에 올리더라도 “API 조회에서 확인된 장기요양기관 등록 건수”로 표시하고, 기준 조회일·누락 가능성·시군구 코드 결합 방식을 함께 적는다. 이 값은 이용 가능 정원이나 현재 서비스 수용력, 실제 이용량, 복지 공백을 뜻하지 않는다. 기존 통합돌봄 프로그램 기록 수와 더해 총 기관 수로 표현하지 않는다. 기존 NHIS 자료의 기관 고유번호가 없어 양 자료 사이 중복은 미확인 상태다.

현재는 API 키 기반 호출과 원본 응답을 검증하지 않았으므로 화면·런타임 연결은 보류한다. 조사 중 원본 CSV, 기관명, 연락처 또는 행 단위 자료를 저장소나 임시 산출물에 저장하지 않았다.

## 재사용 전 필수 확인

1. 공식 포털에서 개발 키를 발급하고 시도별 API 호출이 성공하는지, 인증 실패·페이지 단위·응답 제한 동작을 확인한다.
2. 모든 시군구 코드를 조회해 실제 반환 건수, 코드 누락·중복, 폐업 또는 운영상태 반영 여부를 익명 집계로 산출한다. 총합만으로 전국 완전성을 단정하지 않는다.
3. 기관 유형 코드표와 주소/좌표 제공 여부를 확인한다. 주소가 없는 현 명세만으로 개별 시설 핀을 만들지 않는다.
4. 기존 90,081개 통합돌봄 자원 행과 개념 중복이 예상되므로 별도 집계로 유지한다. 통합이나 중복 제거가 필요하다면 양쪽의 공통 식별자를 확인하기 전에는 진행하지 않는다.
5. 실제 배포 전 공식 라이선스 화면, 갱신 기준일, API 서비스 유지 상태를 다시 확인한다.

## 문화빅데이터 노인여가시설 상품: 도입 보류

원천 상품 페이지는 CSV·무료·연간 갱신, 2026-10-08 업데이트와 전국 노인여가시설이라는 설명을 제공한다. 시설 종류·운영주체, 행정동·도로명·WG 기반 위치정보도 설명되어 있어 시군구로 집계할 잠재력은 있다. 다만 행 수·개별 행 기준일·정확한 컬럼 정의·재사용 라이선스는 읽을 수 있는 공식 상세정보에서 확인되지 않았다. 공식 검색 스니펫에는 `9,538`, 직접 상세 페이지에는 `9,554`와 `520`이 보였으나 모두 용도가 표시되지 않아 어느 숫자도 행 수로 단정하지 않는다.

실제 접근 점검은 다음 단계에서 끝났다.

1. 공식 상품 상세 페이지는 열리고 CSV·무료 표시는 확인됐다.
2. 페이지의 컬럼 정의서 링크를 열었으나 웹 확인 도구에서는 정의서 내용을 가져오지 못했다(원천 상품 정의서 요청은 빈 응답, 파생 상품 정의서 요청은 캐시 미스). 미리보기의 레코드 내용과 실제 CSV 다운로드 경로도 확인하지 못했다.
3. 플랫폼 로그인/회원가입 링크는 보이지만 다운로드에 로그인이 필요한지, 파일을 실제로 내려받을 수 있는지는 확인되지 않았다. 따라서 실제 파일 접근은 **미확인**이다. 이 실패는 원천 서버가 파일을 제공하지 않는다는 증거가 아니다.
4. [공식 저작권정책](https://www.bigdata-culture.kr/bigdata/user/content.do?sq=69)은 저작물에 부착된 KOGL 표시를 확인하라고 하고, 유형과 관계없이 출처 표시를 요구한다. 현재 확인한 상품 상세 페이지 텍스트에는 KOGL 유형을 찾지 못했다. 따라서 `무료` 표시만으로 재사용 조건을 추정하지 않는다.

노인여가시설 원천은 지역아동센터·어린이집과 대상이 달라 직접적인 시설 유형 중복은 예상되지 않는다. 다만 현재 CareMap의 MOHW 자료에 노인여가복지시설 유형별 정원·생활자 집계가 있어 주제상 겹친다. 기관별 위치목록과 지역 집계는 측정값이 달라 보완 가능성은 있지만, 실제 시설 유형·행·지역 분포가 없어 중복 기관 수를 대조하지 못했다. NHIS의 90,081개 통합돌봄 서비스 행과 같은 기관이 들어가는지도 원천 파일과 공통 식별자가 없어 검증하지 못했다.

별도 파생 상품인 [노인 여가생활 지도](https://www.bigdata-culture.kr/bigdata/user/data_market/detail.do?id=d198b8d0-f3db-4fcd-93d0-899ed015e61a)는 전국 시군구별 노인복지시설 수, 안전시설 수, 인구 수를 제공한다고 설명한다. 이 상품의 기준연도·정확한 열·집계 범위도 확인되지 않았다. CareMap에는 이미 2026-10-31 기준 행정동 인구가 있으므로 파생 상품의 인구 열은 정의·시점이 다른 중복 지표가 될 수 있다. 페이지의 `5,927`과 `564` 역시 설명 없는 카운터라 레코드 수로 사용하지 않는다. 파생 상품과 원천을 함께 사용하거나 시설 수를 더하지 않는다.

**결론:** 문화빅데이터 노인여가시설 원천과 파생 상품은 공식 경로로 실제 파일·행 수·컬럼 정의·KOGL 유형을 확인할 때까지 도입을 보류한다. 장기요양기관 API는 명세상 별도 후보지만 인증키 호출 결과가 없어 현재 통합 대상으로 승인된 데이터는 아니다. 이번 조사에서는 새 원본이나 개인·기관별 연락처를 저장하지 않았고, 새 집계도 산출하지 않았다.
