# 의미검색 평가 계획 초안

이 문서는 CareMap의 선택형 의미검색을 기존 규칙 검색과 비교하기 위한 평가 초안이다. 아래 질의는 실제 이용자 기록이 아닌 합성 예시이며, 사회복지 현장 담당자의 검토와 표본 평가 전에는 정확도나 현장 효과로 인용하지 않는다.

## 평가 대상

- **기준선:** 현재 규칙 기반 유형 추출과 키워드 검색
- **의미검색:** 브라우저가 `/api/service-categories`에서 카탈로그의 대·중분류 조합을 받아 `multilingual-e5-small` 임베딩으로 상위 3개 조합 후보를 보여준다. 사용자가 고른 조합은 반복 `intentPair`로 `/api/resources`에 보내 정확한 조합을 후보 조건에 추가하며 기존 규칙 추론과 입력어 검색도 유지한다.
- **평가 단위:** 이용자 질의 1개와 유형 상위 3개, 서비스 후보 상위 8개
- **금지할 결론:** 인구·자료 관측 상태만으로 실제 미충족 수요, 복지 공백, 지원 자격을 판정하지 않는다.

## 측정 방법

1. 현장 담당자 2명이 각 질의의 적절한 서비스 중분류를 독립적으로 지정하고, 의견이 다르면 합의 라벨을 기록한다.
2. 규칙 검색과 임베딩 검색 각각의 **유형 Top-1 적합도**와 **Recall@3**를 계산한다. 사용자가 선택한 유형이 기준 라벨과 맞는지도 별도 집계한다. 현재 임베딩은 모든 질의에 유사 후보를 표시하므로, 모호·범위 밖 질의에서 `무분류/확인 필요`를 택할 수 있는지와 잘못된 유형을 선택하는 비율도 평가한다.
3. 서비스 후보 상위 8건마다 원자료 프로그램명·대분류·중분류가 표시된 근거와 실제 질의가 일치하는지 두 사람이 확인해 **근거 일치율**을 계산한다.
4. 같은 지역·질의 조건으로 기준선과 의미검색의 후보 탐색 시간을 재고, 모델 첫 로드 시간과 캐시 후 응답 시간은 기기·브라우저별로 분리 기록한다.
5. 질의는 이름·주민등록번호·전화번호·실제 상담 기록을 포함하지 않는다. 실제 이용자 질의를 수집하려면 별도 동의·보안 검토가 필요하다.

## 현재 상태와 공개 원칙

- 구현된 모델은 일반 다국어 임베딩 모델이며 사회복지 질의로 미세조정하지 않았다.
- 2026-11-15 로컬 `/api/resources`에서 합성 문장 9개로 규칙 분류만 스모크 확인했다. 확인 당시 코드 기준은 `ebcde19`다. `약속을 정하는 데 도움이 필요해요`와 `몸이 약간 불편해요`는 분류·결과 후보가 없었고, `복지용구가 필요해요`는 `복지용구`, 병원 동행과 집 간호를 함께 말한 문장은 `이동지원`·`방문간호`를 반환했다. 집으로 간호사가 오는 문장, 의사가 집에 와서 진료하는 문장, 명시적 통합지원 문장도 각각 `방문간호`·`방문진료`·`건강-돌봄 통합지원`으로 분류됐다. 이후 `51d2ea7`에서 통합지원 규칙을 좁혔으므로, 위 확인은 현재 HEAD의 동작 검증이 아니다. 실행 시각과 Node·운영체제 버전은 기록되지 않았다. 이는 코드 경로 점검일 뿐 후보 결과의 적합도나 의미검색 모델의 성능을 측정한 것이 아니며, 사람 검토 라벨도 없다.
- CSV에는 28개의 고유 `중분류` 문자열과 34개의 대·중분류 조합이 있다. 같은 `중분류`가 여러 `대분류` 아래 반복될 수 있어(`기타` 6개, `방문간호` 2개) 임베딩 passage에는 대분류명을 함께 넣고 서버는 선택한 조합을 정확히 비교하도록 했다. 설명 문구는 중분류 표기별로 재사용하므로 `기타`처럼 일반적인 유형은 대분류별 설명 차이가 충분하지 않을 수 있다. 이번 pair-aware API와 후보 화면은 코드 정적 검토만 했으며 브라우저에서 확인하지 않았다. 현장 평가에서는 반복 라벨 후보의 구분력과 실제 검색 결과의 근거 적합도를 확인한다.
- 2026-11-15 09:06 KST, Windows PowerShell·Node v24.22.1에서 커밋 `c31ea75`를 임시 포트 8788로 실행해 `/api/health`와 `/api/resources`를 확인했다. health는 `ready: true`, 16개 합성 질의는 모두 HTTP 200이었다. 통합지원 의도를 명시한 6개 표현은 분류됐고, 건강검진·단순 나열·직접 부정·부정 동사 표현 10개는 분류되지 않았다. 통합지원을 원하면서 약물만 원치 않는 혼합 문장도 통합지원으로 분류됐다. 이는 규칙의 의도 분류 경계와 API 응답만 확인한 것으로, 후보 카드의 관련성·의미검색 모델 성능·현장 정확도를 측정한 결과가 아니다. 검토자 라벨도 없다.
- 의미 유형 분석이 90초 안에 끝나지 않거나 오류가 나면 해당 검색은 규칙·키워드 기준선으로 전환한다. timeout fallback은 코드에 구현되어 있지만 발표 장비에서 검증하지 않았다.
- 의미 유형 분석이 오류·시간 초과로 fallback되면 AI 추천 토글을 자동으로 끄고, 이후 검색은 사용자가 다시 켜기 전까지 규칙 기반으로 진행하도록 했다. 반복해서 90초 대기하는 상황을 줄이기 위한 UX 변경이며, 브라우저에서 런타임 확인은 아직 하지 않았다.
- 분류 뒤 `/api/resources` 요청은 15초 안에 응답하지 않으면 오류와 재시도 안내를 표시한다. 이 API 시간 초과는 규칙·키워드 검색으로 전환하지 않는다. 제한은 브라우저의 대기와 요청을 끝내지만, 이미 시작된 서버 측 동기 검색이 중단된다고 보장하지 않는다. 브라우저·발표 장비에서 검증하지 않았다.
- 위 표는 합성 질의 초안일 뿐, 라벨 타당성·모델 정확도·현장 사용성은 검증되지 않았다. 후보 유형은 이용자 확인을 거치도록 했지만, 임베딩 자체의 범위 밖 질의 판별은 아직 구현·검증되지 않았다.
- 결과를 발표할 때는 질의 수, 검토자 수, 모델·기준선별 Top-1/Recall@3, 근거 일치율, 첫 로드·반복 응답 시간을 함께 공개한다. 숫자가 나오기 전에는 성능 향상 주장을 하지 않는다.
- 모델 유사도는 확률이나 서비스 이용 가능성 지표가 아니며, 최종 연락·이용 여부는 이용자와 기관이 확인한다.
